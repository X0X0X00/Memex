# Memex v0.3.1 — Export Poster Design Spec

**Date:** 2026-04-29
**Author:** zzh + Claude
**Status:** Draft (awaiting review)
**Phase:** v0.3.1 (search was deprioritized; this is the second of two remaining v0.3 sub-projects)

---

## TL;DR

Add a single button to the Stats page — **"Export poster"** — that opens a modal letting the user pick one of three social-friendly aspect ratios and download a high-resolution PNG snapshot of their Memex stats:

- **1:1** (1080×1080) — Twitter / WeChat moments / Xiaohongshu
- **9:16** (1080×1920) — IG Stories / Xiaohongshu cover
- **16:9** (1200×630) — Twitter card / OG image / blog hero

The poster is a **purpose-designed wrapped-style card**, not a screenshot of the Stats page. Hero number is total tokens; supporting facts are busiest day, peak hour, total conversations, and (optionally) estimated spend; one 365-day activity heatmap as the visual anchor.

A "Hide spend" checkbox in the modal hides the $ figure for users who'd rather not share it. Branding strip at the bottom: `Memex · 100% local`.

---

## Why

The Stats page is great for self-reflection but useless for sharing — it's a long scrolling dashboard with five fonts and no narrative. A purpose-built poster gives users:

1. A single tappable artifact they can share to social.
2. A "Wrapped" narrative built around their own data.
3. Subtle marketing for Memex (every poster = a referral surface).

We deliberately skip a "screenshot the dashboard" mode because that's not what people actually share — they share polished cards.

---

## Out of scope (v0.3.1)

- Time-range filter (e.g., "Year on Memex 2026"). Defaults to all-time data; per-year filtering is v0.4.x.
- HTML / PDF / CSV export. PNG only.
- Saving multiple cards in one click. Pick a format, get one PNG.
- LLM-generated captions / themes. Static template.
- Custom color themes. Brand palette only.
- Sharing directly to a social network. Save to disk → user does the rest.

## Modal interaction

Triggered by an **Export poster** button at the top right of the Stats page (next to the page title).

```
┌─ Export poster ──────────────────────────────┐
│                                              │
│  Pick a size                                 │
│                                              │
│  [ 1:1 thumbnail ]  [ 9:16 thumb ]  [ 16:9 ] │
│   1080×1080          1080×1920      1200×630 │
│                                              │
│  ☐  Hide estimated spend ($)                 │
│                                              │
│             [ Cancel ]    [ Save PNG → ]     │
│                                              │
└──────────────────────────────────────────────┘
```

The three thumbnails are live `<Poster>` components scaled down via CSS `transform: scale(...)`. They preview the actual current data. They behave like radio buttons: clicking one selects that format, the selected thumbnail gets a 2px ring border (`ring-2 ring-primary`), and the Save button label updates to e.g. `Save 1080×1080 PNG`. Default selection on open: 1:1.

Save flow:
1. User clicks Save → Tauri save dialog opens with default filename `memex-poster-1080x1080.png`.
2. User picks a path.
3. We render the poster at full resolution off-screen, snapshot to PNG via `html-to-image`, write the bytes via Tauri's `fs:write_file` capability.
4. Modal shows a small "Saved → Open in Finder" affordance.

Cancel closes the modal.

## Architecture

### Tech choice: `html-to-image`

Single dependency, ~30KB gzipped. Used by Excalidraw, tldraw, etc. Renders any DOM subtree to PNG via foreignObject + canvas. Pure browser-side, runs inside Tauri's WebView with no extra Rust integration.

Alternatives considered:
- **`dom-to-image-more`** — older, similar API, less maintained.
- **Headless Chrome / Puppeteer** — overkill, would need Rust-side process management.
- **Server-side render (Rust + resvg + skia)** — would need to mirror the entire chart rendering in Rust. Massive scope.

### File structure

```
src/
├── components/poster/
│   ├── Poster.tsx                  # Main component, switches layout by format prop
│   ├── PosterSquare.tsx            # 1:1 layout
│   ├── PosterPortrait.tsx          # 9:16 layout
│   ├── PosterLandscape.tsx         # 16:9 layout
│   ├── PosterHeatmap.tsx           # Simplified static heatmap (no tooltip, no DOM events)
│   └── PosterShared.tsx            # Logo strip, big-number, fact-row primitives
├── components/ExportPosterDialog.tsx   # Modal w/ 3 thumbnails + hide-spend toggle
├── lib/poster.ts                   # snapshotPoster(node, scale) → Uint8Array
└── pages/Stats.tsx                 # Adds the trigger button + dialog state
```

### Data flow

```
Stats page
  ├─ User clicks "Export poster"
  └─ Opens <ExportPosterDialog stats={statsReport} />
       ├─ Renders 3 small <Poster format="..." stats={...} hideSpend={...}/> thumbnails
       └─ User clicks Save
            ├─ Mounts a hidden full-size <Poster> off-screen
            ├─ Calls snapshotPoster(node) → Blob
            ├─ Tauri save dialog → path
            └─ Tauri fs:write_file(path, bytes)
```

### `snapshotPoster` implementation sketch

```ts
import { toPng } from "html-to-image"

export async function snapshotPoster(node: HTMLElement): Promise<Uint8Array> {
  const dataUrl = await toPng(node, {
    pixelRatio: 1,         // node already rendered at native px count
    cacheBust: true,
    backgroundColor: "#0a0e1a",
  })
  // dataUrl: "data:image/png;base64,..."
  const b64 = dataUrl.split(",", 2)[1]
  const bin = atob(b64)
  const bytes = new Uint8Array(bin.length)
  for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i)
  return bytes
}
```

### Tauri side

One new command:

```rust
#[tauri::command]
pub fn save_png(path: String, bytes: Vec<u8>) -> Result<(), String> {
    std::fs::write(&path, &bytes).map_err(|e| e.to_string())
}
```

Plus a capability addition to allow it. Save dialog uses the existing `tauri-plugin-dialog` (already imported) — `save({ defaultPath, filters: [{ name: "PNG", extensions: ["png"] }] })`.

## Visual design

### Background
Dark navy gradient (`#0a0e1a` → `#1e293b`), same as the app icon. Matches Memex brand.

### Typography
- **Hero number**: 200-280px depending on format, white, font-weight 800. Use system stack: `-apple-system, "Inter", sans-serif`. Tabular nums.
- **Hero label** ("tokens"): 32-48px, lower opacity (`#a3b1c6`).
- **Supporting facts**: 22-28px, two columns (label muted, value white tabular).
- **Title strip** ("YOUR YEAR ON MEMEX"): tracking-wider, uppercase, 14-18px, accent green.
- **Footer brand**: small, 12-14px, `#64748b`.

### Heatmap
Reuse the green palette from `ActivityHeatmap.tsx` but simplified for posters:
- Fixed cell size per format (no responsive sizing).
- 53 columns × 7 rows for ~1 year (last 365 days from today).
- No interactive tooltips.
- Single solid background (no rounded cells inside the strip).

### Color accents
Hero number can pick a subtle accent from the model group that consumed the most tokens (`> 50%` of total). The accent is a 4px horizontal line above the hero number; barely noticeable but adds personalization.

- `> 50%` of tokens were Opus → magenta tint.
- `> 50%` were Sonnet → emerald.
- `> 50%` were Haiku → cyan.
- `> 50%` were GPT-4o → green.
- Otherwise (mixed or other) → emerald (default).

This is one decorative line above the hero number; barely noticeable but adds personalization.

## Backend changes

None to the existing stats commands. Everything runs against the data already in `StatsReport`. We only add:

1. New `save_png` Tauri command (10 lines of Rust).
2. New capability permission `fs:write-file` scoped to user-chosen save paths only.

## Number formatting (poster-specific rules)

- **Tokens** — `1234567` → `1.2M` for hero, full number for supporting line.
- **Cost** — `$234.71`. If hidden, the row disappears (not replaced with `***`).
- **Date** — `2025-11-14` (ISO, locale-independent for screenshot consistency).
- **Hour** — `14:00 (local)` so it's always meaningful regardless of where the viewer is.

---

## Privacy

The "Hide spend" toggle is the only privacy lever. Conversation titles, project paths, and tool names are never put on the poster — only aggregate numbers. The user's Memex DB is not exported.

---

## Testing

Pure UI feature; no Rust logic to unit-test beyond `save_png` (one-line wrapper). Test plan:

1. **Snapshot** the three poster components against canned StatsReport fixtures using vitest + jsdom (asserts the right data appears in the DOM).
2. **Manual smoke**: render at full size, eyeball at 100% in Preview.
3. **Cross-platform render**: render once with `hideSpend = true`, once `false`, verify cost row disappears.

No e2e tests — the Tauri save dialog is hard to test reliably and the value isn't proportional.

## Risks

| Risk | Mitigation |
|---|---|
| `html-to-image` produces blurry text on retina | Pre-render the source node at native pixel size; let `html-to-image` use `pixelRatio: 1`. |
| Web fonts don't load before snapshot | Use system fonts only — no remote font fetches anyway. |
| Heatmap pivots wrong on locale | All date logic uses UTC for the heatmap snapshot (only the "peak hour" line uses local TZ, with explicit `(local)` suffix). |
| Memex.app file write rejected by sandbox | Use Tauri's allowed save dialog path; avoid silent writes. |
| Large user data slow to render | Heatmap is 53×7 cells = 371 nodes; total poster DOM <500 elements. Fine. |
